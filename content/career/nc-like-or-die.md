## AI(ML) 기반 애니메이션 노티파이 추천 (R&D) {#ml-notify}

발 본 궤적으로 학습한 ONNX 모델을 에디터에서 실행해 **풋스텝 노티파이를 찍을 프레임 추천·일괄 적용**하는 툴.

### 규칙 기반 판정의 한계

애니메이션마다 기준 높이가 다르고, 발이 가장 낮은 프레임과 실제로 땅을 딛는 프레임이 어긋나는 경우 다수. 발을 끌거나 미끄러지는 동작도 접지로 잘못 잡혀 임계값 하나로는 판정 불가.

대신 기존 에셋에 사람이 찍어 둔 노티파이가 이미 있어 정답 라벨로 활용. **기존 판정 기준을 그대로 학습**한 모델 훈련·적용.

### 구성

규칙은 전처리에만 사용. 애디티브 애니메이션과 발 속도 25cm/s 미만 구간을 걸러 탐색 범위 축소, 프레임별 접지 판단은 모델이 담당.

발 본 궤적 → **PyTorch 학습 → ONNX 변환 → UE5 NNE(NNERuntimeORT) C++ 인퍼런스** 순서로 에디터에 연결.
모델 캐싱으로 에셋마다 다시 불러오지 않음.

### 툴

후보 목록과 일괄 적용은 Slate 윈도우로 구현.
예전 범용 노티파이와 전용 노티파이를 나눠 추천, **마이그레이션도 같은 툴에서** 처리.

피처 추출과 후처리 규격은 학습 파이프라인과 똑같이 고정. 전처리가 조금만 달라도 성능이 무너지기 때문.

### 검증

- 이벤트 매칭 **F1 0.899** (Precision 0.876 / Recall 0.923), 허용 오차 0.1초 (30Hz 기준 3프레임)
- 발이 닿는 클립과 닿지 않는 클립을 나눠 측정, **닿지 않는 클립의 노티파이 오생성 0건**

**Recall 우선 설정**
- 추천 결과는 Slate 창에서 사람이 확인 후 적용
- 오추천은 체크 해제 한 번으로 폐기, 누락은 애니메이션을 직접 돌려 보며 프레임을 찾아야 해 비용이 더 큼
- 오추천이 가장 치명적인 무접지 클립(발이 닿지 않는 클립)은 따로 측정, **생성 0건**으로 차단

## Unreal Slate 기반 백그라운드 알림 (R&D) {#background-notify}

오래 걸리는 작업이 끝나면 **별도 Slate 창으로 알리고, 알림 클릭 시 대상 창을 앞으로 가져오는** 기능. (Windows 전용)

### 표시 조건

**아크 레이더스의 대기창**을 레퍼런스로, 게임 매칭이나 로딩 완료 같은 중요 이벤트 발생 시 게임이 백그라운드에 있으면 알림 표시. 게임이 앞에 있으면 표시하지 않음.

인게임 외에도 **라이브 코딩 완료 시** 팝업을 띄워 완료를 바로 알 수 있게 함, **작업 이터레이션** 단축. 패치 완료 델리게이트를 받아 에디터가 앞에 있어도 표시.

[이전 프로젝트에서 만든 트레이 아이콘 풍선 알림](#prasia--tray-notify)을 **게임 전용 Slate 배너**로 발전시킨 기능.

[백그라운드 알림 데모](#like-or-die-lab--notify)

### 포그라운드 정책 우회

윈도우는 백그라운드 프로세스가 자기 창을 앞으로 올리는 것을 차단. 그래서 알림 창을 **topmost + 처음엔 포커스를 받지 않는 창**으로 띄우고, 사용자 클릭을 권한 획득 계기로 활용.

클릭을 받으면 바로 대상 창을 올림. 첫 클릭이 OS 의 창 활성화에 쓰여 버린 경우에는 **앱 활성화 콜백과 커서 좌표**로 알림 클릭 여부를 거슬러 확인 후 올림. (한 번 쓰고 해제)

올리는 대상은 첫 top-level 창의 루트 핸들, 최소화 상태면 먼저 복원.

### 창 구성

게임 창과 따로 노는 창. 타이틀바와 버튼 없음, 창 단위 투명도 사용.
주 모니터 작업 영역의 오른쪽 아래에 DPI 보정해 배치, 5초 뒤 자동으로 닫힘. (티커는 약참조로 캡처)

알림에 **플레이어가 커스터마이징한 캐릭터를 캡처한 섬네일**을 넣어, 플레이어마다 다른 자기 캐릭터가 보이는 알림 표시.
배너 이미지는 패키징에 포함되도록 에셋으로 관리, 불러오지 못하면 단색으로 대체.

## 언리얼 에디터 / 런타임 로드 성능 분석 및 감축 (R&D) {#load-performance}

Unreal Insights 트레이스를 **전후 1:1로 비교**해(같은 맵, 같은 DDC 조건, 대조군 포함) 병목 파악, 필요하면 **엔진 소스에서 직접** 수정. 주요 수치는 [성과 지표](#impact)에 그래프로 정리.

### 1. 나이아가라 상속 드리프트: 로드할 때마다 재컴파일되던 문제

| 지표 | 전 | 후 | 변화 |
| --- | ---: | ---: | ---: |
| VFX 폴더 로드 | 18.4초 | **4.5초** | −76% |
| 이미터 머지 | 299회 / 14.7초 | **15회 / 0.7초** | −95% |
| 중복 로드 | 14.6초 | **1.1초** | −92% |
| 강제 동기 플러시 | 97건 | **1건** | −99% |
| PIE 50ms 초과 프레임 | 204 | **114** | −44% |

**분석**
Insights 에서 이미터 머지 **290회, 14.4초** (캡처의 10.2%, 전부 게임 스레드) 소요 확인.
머지 ChangeId 로그를 켜고 새로 로드해 자식 / 부모 ChangeId 3종 대조, 다시 저장해도 고쳐지지 않는 이유를 실측 2건으로 확인.

**원인**
동기화되지 않은 상태에서 ChangeId 신규 발급, 머지 직후 dirty 표시 해제 → 로드할 때마다 머지 → 링커 리셋 → 강제 플러시 반복.

**조치**
장기간 반영되지 않았던 부모 변경을 **에셋 111개 일괄 리세이브**로 해소.
재발 방지용 **에디터 서브시스템** 신규 제작. 패키지 저장 이벤트를 받으면 AssetRegistry 참조자를 BFS 로 따라가 자손 에셋 수집, 머지와 저장 유도.

### 2. Mutable 플러그인 동기 로드: 참조자 클래스 필터 3줄

| 지표 | 전 | 후 | 변화 |
| --- | ---: | ---: | ---: |
| 에디터 첫 프레임 | 20.8초 | **9.2초** | −56% |
| Mutable 틱 | 19.0초 | **7.6초** | −60% |
| 첫 틱 에셋 로드 | 9.2초 | **1.6초** | −83% |
| 동기 패키지 로드 시간 | 17.4초 | **7.0초** | −60% |
| 불필요한 로드 스코프 | 약 19만 건 | **0건** | −100% |

**분석**
첫 프레임 20.84초 중 **19.0초가 Mutable 스트리밍 틱 한 구간**. 게임 스레드 스택을 export 해 확인.
같은 플러그인의 컴파일러 경로는 클래스 확인 후 로드한다는 점과 비교해 수정 위치 결정.

**원인**
`GraphTraversal::GetNodeGroupObjectNodeMappingImmersive` 가 참조자를 클래스 확인 전에 전부 로드 → 캐릭터 BP / AnimBP 를 거쳐 애님 시퀀스 200여 개가 첫 프레임에 동기 로드.

**조치**
같은 함수에서, 로드 전 **AssetData 로 클래스 확인** 후 Mutable 클래스가 아니면 바로 `continue` 하는 3줄 추가. 동기 패키지 로드는 388회에서 372회로 거의 그대로지만 시간은 절반 아래로 감소.
남은 8.5초는 CO 계층 자체를 로드하는 비용이라, 플러그인 설계상 한계로 문서화.

**엔진 5.8 업데이트**
이후 5.8 업데이트에서 엔진도 같은 자리(GraphTraversal.cpp)를 수정, 방식은 조금 다름. 내 방식은 참조자를 하나씩 보며 건너뛰기, 5.8 은 `Filter.ClassPaths.Add(UCustomizableObject)` 로 **조회 단계에서부터** 걸러 냄.

### 3. 인게임 이펙트 스폰 비용: 비동기 프리로드 + 나이아가라 컴포넌트 풀링

쿠킹 빌드에서 A / B / C 세 세션으로 측정.

| 지표 | 전 | 후 | 변화 |
| --- | ---: | ---: | ---: |
| 첫 발사 프레임 | 28.8ms | **16.1ms** | −44% |
| 첫 발사 프레임 (2라운드) | 25.7ms | **12.0ms** | −53% |
| 그 프레임의 동기 로드 | 17.7ms (12회) | **5.1ms (2회)** | −71% |
| 컴포넌트 등록 | 2,640회 | **324회** | −88% |
| GC 대기 중인 죽은 컴포넌트 | 1,384개 | **296개** | −79% |
| GC 1회 파괴 비용 | 3.2ms | **0.8ms** | −74% |

**조치**
이펙트를 쓰기 전에 미리 비동기로 불러와 인게임 캐시에 유지. GC 가 지웠다가 다시 불러오는 일 방지 목적.
원샷 FX 스폰을 풀링 경로로 전환, EffectType 티어 8종 정리.

**측정 조건**
자동 / 병렬 GC 를 끄고 수동 GC 로 시점 고정, 세션 반복으로 같은 결과 재현 확인.

**트레이드오프**
VRAM 56MB 증가. 이 비용과 사용 규칙을 **팀 가이드라인**으로 문서화.

### 4. 매치 시작 저프레임: 애님 PostLoad 2단계 감축

**1단계 결과**

| 지표 | 전 | 후 | 변화 |
| --- | ---: | ---: | ---: |
| 저프레임 구간 | 53초 (11~50fps) | **32초 (40~80fps)** | −40% |
| 데이터 모델 PostLoad (893회) | 9.0초 | **0.06초** | −99% |
| 애님 1개 PostLoad | 17.6ms | **6.3ms** | −64% |

**2단계 결과**

| 지표 | 전 | 후 | 변화 |
| --- | ---: | ---: | ---: |
| 시퀀스 PostLoad (829회) | 5.9초 | **0.05초** | −99% |
| 로드 구간 프레임 시간 합 | 46.7초 | **37.2초** | −20% |
| 16.7ms 초과 프레임 | 497 | **306** | −38% |

**분석**
매치 시작 후 약 60초 동안 10~30fps (에디터 빌드)로 떨어지는 구간을 Insights 로 분해. 게임 스레드 23초 중 **15.2초 (66%)가 비동기 로딩 처리**.

정체는 애님 시퀀스 PostLoad. 프레임마다 애님 1개씩 들어오며 17.6ms (에디터 전용 데이터 모델 11.3ms + 시퀀스 6.4ms) 소요, RT 는 6.5ms 라 GT 바운드.

**로드 주체**
스트리밍 Verbose 로그의 요청 루트와 AssetRegistry 의존성 클로저를 스크립트로 대조. 스폰 무기의 애님 DB 6개 (DB 하나에 하드 참조 190~230개)가 **878개 패키지 (93% 가 AnimSequence)** 를 끌고 오는 것 확인.

**1단계: ControlRig 초기화 미루기**
애님 PostLoad 때 ControlRig 하이어라키 초기화를 미루는 엔진 콘솔 변수를 ini 로 적용.
쿡 경로는 eager 초기화라 산출물에 영향 없음을 엔진 코드로 확인.

**2단계: 스켈레톤 GUID 불일치 정리**
남은 6.3ms 추적을 위해 엔진 PostLoad 체인에 임시 트레이스 스코프 32개 삽입. 99.9% 가 스켈레톤 GUID 불일치로 인한 **로드할 때마다 스켈레톤을 교체하는 비용**.

Verbose 로그로 해당 애님 548개 탐색, 버전 관리 이력에서 "스켈레톤 본 머지 후 애님을 다시 저장하지 않은" 시점 특정.
**543개 일괄 재저장**, 스켈레톤 저장 시 영향받는 애님 재저장을 안내하는 에디터 서브시스템 추가.

**범위 확인**
패키징 빌드에서 재측정 시 이 구간 없음 (비동기 로딩 처리 0.05초). 그래서 **에디터 체감 개선**으로 범위 명시.
에디터 비동기 로딩 스레드도 A/B 시험. 저프레임은 0초가 되지만 비용이 로딩 화면으로 옮겨 가고 엔진 레이스 이슈가 있어 보류.

### 5. 120fps 병목 분석: 클라 틱 / 애님 평가 비용 줄이기

**분석**
PIE 60초 트레이스에서 **GT 13.7ms 바운드**. RT 7.5ms, RHI 9.7ms 는 여유, VSync 대기도 아님. 에디터 전용 5.9ms 를 빼면 스탠드얼론 기준 GT 약 7.9ms 라 판정 기준부터 바로잡음.

게임 쪽 GT 최대 항목은 워커 애님 체인 대기 **프레임당 2.0ms (월드 틱의 43%)**. 1인칭일 때 숨어 있는 3인칭 풀바디가 RigLogic 0.63 + ABP 0.49 + 클로스 0.31×2 (본체 + 그림자 팔로워 중복 시뮬레이션) 사용.

컴포넌트 틱 프레임당 120회, dumpticks 로 빈 틱 / 디버그 전용 / 권한 게이트 틱 분류.

**조치: 틱**
- HUD 가 엔진 액터 틱과 별개로 매 프레임 한 번 더 돌던 경로와 빈 HUD 틱 제거
- 서버 전용 틱은 클라이언트에서 비활성화
- 디버그 전용 틱은 콘솔 변수를 켰을 때만 실행

**조치: 애님 평가**
- 그림자 메시 클로스를 리더 포즈에 묶어 중복 시뮬레이션 제거
- 마네킹에 URO 적용, 화면 밖에서는 몽타주만 평가
- 1인칭일 때 숨은 통합 바디에 강제 LOD 옵션 추가
- 무기 메시 (탄창 메시 포함)에 화면 밖 틱 옵션 추가

## 사운드 시스템 (Wwise) {#sound}

Wwise 내장 공간음향 대신 **차폐 / 밀폐도를 직접 계산하는 계층**과 그 값을 실어 나르는 **재생 기반 계층** 설계. 차폐 계산 흐름은 [공간음향 데모](#spatial-audio)에서 직접 조작 가능.

Wwise Spatial Audio 는 Room / Portal 을 사람이 미리 배치하는 방식. Like Or Die 는 플레이어가 블록을 설치해 게임 중에도 공간이 바뀌므로 차폐 **실시간 계산** 방식 채택.

- **사운드 서브시스템 (재생 창구 + 컴포넌트 풀링)**
  모든 재생이 이 창구 하나를 경유. 소유자 없는 오디오 컴포넌트를 **대여 / 반납**하는 풀이라, 원샷 3D 사운드도 스폰 비용 없이 차폐 값 적용 가능.
  보유량은 물리 RAM 에 비례해 설정, 남는 컴포넌트는 타이머로 조금씩 회수.
  대여 시 Wwise 게임오브젝트를 새로 등록해 이전 스위치 / RTPC 잔존 방지. 재생 중에는 뱅크 / 이벤트 로드 핸들을 유지해 GC 로 인한 소리 끊김 방지.
- **차폐도**
  레벨 콜리전 AABB 를 **셀 그리드**로 변환, 직선 레이가 막혔을 때만 **A\* 우회 경로 길이의 비율**로 차폐 계수 산출.
  그리드는 **이중 버퍼**라 탐색과 재구축이 서로 막지 않음, 평소에는 청취자 주변만 증분 갱신.
- **들리는 방향 (가상 음원)**
  막혔을 때 소리가 벽을 뚫고 오지 않도록 A\* 경로를 청취자에서부터 따라가 **아직 보이는 마지막 점(문, 벽 끝)에 가상 음원** 배치, 거리는 경로 길이 사용.
  Wwise 게임오브젝트 위치를 그 자리로 옮겨 소리가 문 쪽에서 들림. [공간음향 데모](#spatial-audio)에서 '우회 방향에서 듣기'를 켜고 끄며 비교 가능.
- **밀폐도**
  캐릭터 머리 위치에서 **26방향 비동기 레이** 발사, 맞은 거리 분포로 공간의 크기와 막힌 정도 계산.
  위 / 가운데 / 아래 방향별 가중치와 맞은 표면의 재질별 흡음 계수 반영.
- **실시간 계산 부하 관리**
  정적 오브젝트는 AABB 로 캐싱, 블록처럼 새로 생기는 동적 오브젝트도 추가 시점에 AABB 로 캐싱.
  탐색은 **Unreal Tasks 멀티스레드**로 돌려 게임 스레드 부하 감소, 레이는 **비동기 트레이스**로 쏴 히치 감소.
  그리드 갱신 / 차폐 / 밀폐도는 각자 다른 주기의 타이머로 실행, 게임 스레드 프레임이 기준 아래로 떨어지면 **계산 자동 중단**.
- **관전 / 리플레이 대응**
  청취 기준점이 위치 기반이라 관전, 리플레이, 폰 교체 모두 같은 경로로 동작.
- **Wwise 로컬라이제이션 (R&D)**
  게임 언어 설정 변경 시 **Wwise 음성 언어도 함께 전환**. 언어 전환 실패 시 콜백 처리.
  언어 전환과 재생 확인용 치트, 가이드 제작. Wwise Motion 패드 진동은 '그 외' 항목 참고.
- **오프라인 렌더 / 검증 도구**
  WAAPI 로 이벤트 목록을 읽고 switch / state 를 적용해 **오프라인 렌더링으로 바로 들을 수 있는 파일** 추출. bank json 으로 적용 가능한 조합도 추출, 엔진을 켜지 않고 Wwise 결과물 확인 가능.

## 리플레이 시스템 {#replay}

엔진 리플레이(DemoNetDriver)는 복제 스트림 기록·재생까지만 제공. **저장 주체, 재생 전용 폰 / 카메라, 구간 절단, Seek 후 상태 복원, 관전 대상 추적**은 프로젝트에서 구현.

- **녹화 / 저장**
  리플레이 서브시스템이 녹화 시작, 종료, 저장 경로 관리.
  **클라이언트 녹화와 데디케이티드 서버 녹화** 모두 지원, 커스텀 네트워크 버전으로 빌드가 다른 파일은 명확히 거부.
  클라이언트 녹화는 내 시점 재생에 적합하나 동기화 범위 밖은 기록되지 않음, 서버 녹화는 전 범위를 담는 대신 파일 송수신과 보관 비용이 서버에 발생. 재생 상태 보유 책임은 서브시스템에서 DemoNetDriver 로 이전.
  보관 정책, 기능 숨김, 녹화 주기 상향도 추가.
- **재생 전용 컨트롤러 / 폰 / 카메라**
  일시정지 중에도 카메라를 움직일 수 있게 입력 경로 분리.
  자유 카메라 모드 추가, 스펙테이터 카메라를 PlayerCameraManager 경유로 통일. 뷰 타겟 설정 순서 문제도 보완.
- **구간 리플레이**
  녹화 중 킬 / 데미지 이벤트를 기록해 두고 **그 이벤트를 기준으로 구간만 잘라 재생**. (Seek → 정해진 시간 재생 → 로비 복귀)
  이벤트는 네트워크 식별자로 탐색, 라이브 리플레이 끝으로 점프하는 동작은 콘솔 변수로 분리. Seek 재진입 검증, 시간 표준은 내부 절대시간과 UI 상대시간으로 분리.
- **Seek 후 상태 복원**
  체크포인트에 없는 상태는 Seek 뒤에 되살아나지 않음. 그래서 Seek 종료 시점에 **표현을 한 번에 다시 맞춤**.
  복제되지 않던 값은 **리플레이 전용 복제 조건**으로 추가, 실제 플레이의 네트워크 대역 증가 없음. 장비 슬롯 미러 값, 팀 식별자 복제, 갱신 주체 단일화, 동적 컴포넌트 초기 생성 전환도 같은 흐름.
  인스턴스드 메시는 시각 상태 콜백이 메시를 갱신하므로 복제 대상에서 제외, Seek 후 남는 인스턴스 정리 경로 마련.
- **관전 대상 추적**
  추적 기준을 폰에서 플레이어 상태로 변경, 폰이 바뀌어도 계속 추적.
  1인칭 관전 스코프와 부착 액터 렌더링 통일, 커스텀 요 복제로 시선 보정.
- **UI / 안정화**
  리플레이 HUD 와 타임라인 위젯, 로비 목록 (매치 정보 / 리비전), 로딩 스크린, 종료 시 로비로 돌아가는 페이드 제작.
  재생 중 거점 거리와 목표물 아이콘 표기 보정, 촬영·검증용 HUD 토글 치트 추가. 동적 서브레벨 미탐색, 리스너 해제, 타임라인 이동 크래시 수정.

## 무기 프리뷰 툴 (R&D) {#weapon-preview}

게임 실행 없이 에디터에서 **무기 / 부착물 뮤터블 조합과 스탯 증감폭**을 확인하는 툴.

- **조합 미리보기**
  에디터 메뉴에서 열고 무기와 부착물을 고르면, 데이터 테이블의 뮤터블 파라미터를 그대로 적용해 **커스터마이징 오브젝트를 즉석에서 조합·3D 표시**. PIE 나 패키지 실행 없이 조합 결과 확인.
- **비동기 로드**
  뮤터블 인스턴스, 메시, 애니메이션 **비동기 로드**. 동기 로드 옵션도 유지.
- **뷰포트 조작**
  좌클릭 회전, 중클릭 팬, 카메라 / 무기 초기화 지원, 고른 애니메이션 반복 재생.
- **스탯 시트**
  **기본 스탯과 부착물 적용 증감폭** 동시 표시. 슬롯마다 부착물 이름과 증감값을 짝지어 표시, 퍼센트 / 정수 항목 구분. 테이블 오입력이나 조합 스탯을 바로 눈으로 확인.

## 그 외 {#etc}

- **나이아가라 1인칭 렌더 전파 (R&D)**
  엔진 기본 나이아가라 애님 노티파이는 스폰한 컴포넌트에 FirstPersonPrimitiveType 을 넘기지 않음. 그래서 1인칭 메시 이펙트가 1인칭 렌더 경로를 타지 못함.
  이펙트 스폰 훅만 오버라이드한 **서브클래스**로 해결. 엔진 수정 없음, 3인칭 / 월드 이펙트용 옵트아웃 플래그 추가.
- **간이 런처 (R&D)**
  팀 스토리지에서 빌드를 받아 오는 반복 작업을 줄이려고 Python 으로 제작. 빌드 다운로드부터 실행까지 바로 연결.
  실행 인자 프리셋 (서버 / 클라이언트 분리 실행, 접속 대상, 리비전 표시), 로컬 빌드, 로그 분리 지원.
- **게임패드 진동**
  피격 방향별 약한 진동과 사망 시 강한 진동을 ForceFeedback 으로 구현, 수류탄 폭발음은 **Wwise Motion** 으로 패드 진동 출력.
  패드 종류별(DualSense / DualShock4 / Xbox) 출력 경로를 Wwise Motion 에 연결, 트리거 진동까지 확인.
  에디터 없이 진동과 트리거를 시험하는 **단일 실행 테스트 도구**, 연결된 모든 패드로 진동을 미리 보는 에디터 보정, 비프로그래머용 채널 → 모터 매핑 가이드 제작.
